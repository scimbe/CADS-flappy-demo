# art-reference-hints.txt — keyword -> factual hint, one per line, "keyword:hint text".
# art-handler.sh case-insensitively substring-matches each keyword against the customer's
# prompt and appends any matched hints to the LLM's system prompt. This exists because a
# small local model (litellm/Ollama-backed, no web knowledge beyond training) reliably
# misses specific brand/mascot/franchise identities that claude gets right from broad
# training knowledge (real example, 2026-08-16: "freebsd theme" -> local-mistral-small
# picked generic blue with no bird emoji at all; claude correctly picked red + the FreeBSD
# "Beastie" devil). Turning "does the model already know this" into "can the model use a
# fact it's handed" closes most of that gap without depending on claude at all. Add more
# lines as new gaps get reported -- keep each hint short (it's added to every matching
# request's prompt) and factual (color/symbol/vibe, not full paragraphs).
